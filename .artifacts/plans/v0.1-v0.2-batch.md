## Acceptance Criteria (derived from issue bodies + GOALS.md)

### v0.1
- [ ] **#3 XAIP: ontology composition schema** — `schemas/composition.schema.json`
  exists and validates `knowledge-bases/*/composition.yml`. The composition
  schema specifies how entity-type + relationship-type atoms compose into
  an ontology, with version pinning and provenance requirements toggles.
- [ ] **#4 Five atom type schemas with provenance + confidence primitives** —
  `schemas/{entity-type,relationship-type,provenance-atom,fact-type,confidence-primitive}.schema.json`
  exist; each is a JSON-Schema-2020-12 document; at least one example atom
  per type exists under `atoms/<type>/` and validates. Every fact-typed atom
  carries a `provenance: [...]` array; every assertion carries a
  `confidence: {...}` block per the confidence-primitive schema.
- [ ] **#5 Mnemosyne's internal model expressed in knowledge-atoms** —
  `knowledge-bases/mnemosyne/composition.yml` exists; references real atoms
  by ID; passes composition validation; covers Mnemosyne's domain
  (cross-session semantic memory): Conversation, Turn, Topic, Fact, Source
  entities and their relationships.
- [ ] **#6 Round-trip export/import test** — `scripts/export.py` produces
  `exports/catalog.json` (canonical, deterministic); `scripts/import.py`
  reads that JSON and reconstructs the in-memory atom set; a pytest test
  asserts the round-trip preserves content + provenance + confidence
  bit-for-bit (per success criterion in GOALS.md §v0.1).

### v0.2
- [ ] **#8 Federation protocol for distributed knowledge graphs** —
  `schemas/federation-manifest.schema.json` exists and defines the
  on-the-wire manifest a knowledge-base publishes for federation
  (base URL, atoms checksum, supported reference protocols, trust
  declarations). At least one example manifest validates.
- [ ] **#9 Cross-base reference resolution** — `scripts/resolve_refs.py`
  resolves `<base>://atoms/<type>/<id>@<version>` URIs against a manifest
  registry; pytest test covers (a) same-base resolution, (b) cross-base
  resolution via federation manifest, (c) version-pinning fallback,
  (d) unresolvable reference returns explicit error (no silent fallback).
- [ ] **#10 Confidence-weighted merge** — `scripts/merge.py` merges two
  fact sets that may contradict on the same `(subject, predicate)`,
  producing a single set whose confidence reflects evidence aggregation
  per the rule under `rules/contradiction-handling/`. Pytest covers
  (a) agreement increases confidence, (b) contradiction is preserved as
  contradiction-handling per the active rule, (c) low-confidence facts do
  not displace high-confidence ones without sufficient corroboration.

## Rationale + Alternatives Table (per Code.md §11.1)

| Alternative | Pros | Cons | Verdict |
|---|---|---|---|
| **JSON + JSON-Schema** (chosen for atoms, schemas, exports) | Already the pattern in prompt-atoms / agent-atoms siblings; jsonschema 2020-12 lib in Python; deterministic round-trip; canonical form trivially diffable | Verbose for humans editing by hand | **Chosen** — consistency across the catalog ecosystem is the dominant concern; humans rarely hand-author atoms after the initial seed |
| **YAML for atoms** | Human-friendlier; spec calls compositions `composition.yml` so YAML is already in the catalog | Multiple-document YAML, anchor handling, and float-preservation across round-trip add real risk to the success criterion in GOALS.md §v0.1 (no loss of provenance or contradiction info) | Mixed — YAML for **compositions** (matches existing convention); JSON for **atoms** (matches sibling catalogs and makes the round-trip test mechanically verifiable) |
| **Single mega-schema discriminated by `type`** | Fewer files | Loses per-type clarity; harder to evolve one atom type without churning the others; siblings keep them separate | Rejected |
| **No round-trip test, just schema validation** | Less surface | Fails the explicit GOALS.md §v0.1 success criterion ("merge knowledge bases via export/import without loss of provenance or contradiction information") | Rejected |
| **Defer federation to v0.3** (do nothing for #8/#9/#10) | Shrinks PR | Violates the assignment — the orchestrator chose v0.1+v0.2 as one wave | Rejected |
| **Mock the round-trip path with stub data** | Faster | /spawn §7 Tester charter explicitly hunts for "mocked integration where TL plan said real"; success criterion requires real round-trip | Rejected |

## Seed Commit (lands first)

**OWNS** (shared interfaces, lands before any feature commit):
- `scripts/validate.py` — JSON-schema validator walking `atoms/`, `schemas/`,
  `knowledge-bases/`. Uses `jsonschema` Draft 2020-12. Catches malformed
  YAML and JSON. Exit non-zero on any validation error.
- `project.yaml` — minimal:
  ```yaml
  name: knowledge-atoms
  version: 0.1.0
  tooling:
    test_command: python3 scripts/validate.py && python3 -m pytest -v
  ```
- `schemas/knowledge-atom.schema.json` — base schema every atom file
  validates against. Includes the provenance + confidence primitives
  required by #4 (provenance is an array of provenance refs; confidence
  is a `{value: 0..1, basis, sources_count}` triple).
- `schemas/composition.schema.json` — composition skeleton for #3 and #5.

## Test Strategy

- **Unit:** schema validation per-file; export/import canonicalization;
  reference resolution edge cases; merge arithmetic.
- **Integration:** Mnemosyne composition validates against the real atom
  set, not a stub. Round-trip uses the real `export.py` / `import.py` on
  the real `atoms/` tree.
- **NO MOCKS** for: jsonschema validation, file I/O against `atoms/`,
  the export/import round-trip, the reference resolver against a real
  manifest. /spawn §7 explicitly hunts these.
- **Adversarial focus areas (per /spawn §7 Tester charter):**
  - Did C3 deterministic export use sorted keys? (Round-trip lies if not.)
  - Does the merge code silently drop one side of a contradiction?
  - Are there `try/except: pass` swallows in `resolve_refs.py`?
  - Are any tests skipped, `xfail`'d, or stripped of assertions?
  - Does C2 reference atoms that C1 didn't actually create?

## Adversarial self-pass (Code.md §11.6) — to run before PR

- Hidden assumptions: confidence math assumes independent evidence
  (named in `rules/contradiction-handling/`).
- Undocumented invariants: composition `version` is pinned; the
  resolver must reject unpinned refs in cross-base mode.
- State corruption: export must produce identical bytes on identical
  input; `dict` key ordering is the obvious risk.
- TOCTOU: not applicable — no concurrent writers in this catalog.
- Logical edges: empty `atoms/` directory (validator should report
  zero atoms, not crash); composition referencing a missing atom
  (must fail loudly).
